# 03 · กฎการเทรด

## ตลาด

**ตลาดเป็นค่าของแต่ละเหรียญ ไม่ใช่ของทั้งระบบ** (`symbols[].market`, [decisions #26](../decisions.md)) — profile เดียวถือ BTC บน perp และ ETH บน spot พร้อมกันได้ · เหรียญหนึ่งเลือกได้ตลาดเดียว

| `market` | ความหมาย |
| --- | --- |
| `usdtm_perp` | USDT-M perpetual futures — margin แบบ `isolated`, position mode แบบ `one_way` |
| `spot` | ซื้อขายของจริง — **long-only** |

### `usdtm_perp`

`one_way` แปลว่า **หนึ่ง symbol มีสถานะได้ฝั่งเดียวเสมอ** ห้ามถือ long กับ short พร้อมกัน จุดเดียวที่ระบบเข้าใกล้การละเมิดข้อนี้คือตอน flip จึงต้องมีโปรโตคอลเฉพาะ (ด้านล่าง)

มี leverage ต่อ symbol (`leverage`) ใต้เพดานระดับ profile (`max_leverage`) ผลที่ตามมาที่ใหญ่ที่สุดคือ **ไม้ถูกปิดโดย exchange ได้เองที่ราคา liquidation แม้ยังไม่เกิดสัญญาณฝั่งตรงข้าม** ซึ่งเป็นสิ่งที่ระบบ spot ไม่มี — `min_liq_buffer_pct` ใน [06](06-risk-and-execution.md) คือสิ่งเดียวที่กันเรื่องนี้

### `spot` — long-only

**สัญญาณแดงบนเหรียญ spot แปลว่า "ขายออกให้แบน" จบ** ไม่มีขาเปิดตาม เพราะขายชอร์ตบน spot ทำไม่ได้ — ผลคือ **ไม่มี flip บน spot** โปรโตคอลสองขาด้านล่างเป็นของ `usdtm_perp` เท่านั้น และ `flip_aborted` / `residual_qty` / `unmanaged` ที่ตามมาจากมันก็เกิดบน spot ไม่ได้เช่นกัน

สิ่งที่ไม่มีอยู่จริงบน spot — **ไม่ใช่มีแล้วเป็นศูนย์**: liquidation · funding · leverage (บังคับ `leverage = 1` เพื่อให้สูตรใน [05](05-position-sizing.md) เดินเส้นทางเดียว) · ฝั่ง short (`allow_short` ต้อง false และไม่มี `bucket_quote_short`) · ธง `reduce_only` ของออเดอร์

กฎที่เหลือทั้งหมด — กฎไม้เรียว, การเข้าที่แท่งสัญญาณเท่านั้น, การไม่เปิดทับฝั่งเดิม, cold start — ใช้เหมือนกันทั้งสองตลาด

## เข้าไม้

| สัญญาณ | ถืออยู่ | ทำอะไร |
| --- | --- | --- |
| `long_signal` | ไม่มีสถานะ | เปิด long |
| `long_signal` | ถือ short | **flip** — ปิด short แล้วเปิด long ในแท่งเดียว |
| `short_signal` | ไม่มีสถานะ | เปิด short |
| `short_signal` | ถือ long | **flip** — ปิด long แล้วเปิด short ในแท่งเดียว |
| `long_signal` | ถือ long | ไม่ทำอะไร — ไม่มี pyramiding |
| `short_signal` | ถือ short | ไม่ทำอะไร |

เข้าที่จุดสัญญาณตาม [02](02-action-zone.md) เท่านั้น — ไม่ใช่ทุกแท่งเขียว ไม่ใช่ทุก `longcond`

ขนาดไม้มาจาก [05](05-position-sizing.md) โดยใช้ bucket และเพดานของ**ฝั่งนั้น**

### `allow_short = false`

มีสองชั้น — สวิตช์ระดับระบบกับสวิตช์รายเหรียญ ผลจริงคือ AND ของทั้งสอง ([07](07-data-and-config.md))

เมื่อปิดฝั่ง short ไว้ `short_signal` จะทำได้แค่ **ปิด long** เท่านั้น ไม่เปิดฝั่งใหม่ และไม่ต้องเรียก Confluence Judge ไม่ต้องคำนวณขนาดไม้ — พฤติกรรมกลับไปเหมือนระบบ long-only เดิมทุกประการ

## ออกจากไม้

ออกเมื่อเกิดสัญญาณฝั่งตรงข้าม — ปิดสถานะทั้งหมด ไม่มีการปิดบางส่วน

เอกสารต้นทางไม่แยกระหว่าง take profit กับ stop loss ที่จุดนี้: **แดงแรกคือแดงแรก** จะกำไรหรือขาดทุนก็ออกเหมือนกัน การเพิ่มเงื่อนไข "รอให้กำไรก่อนค่อยออก" คือการเปลี่ยนระบบ ไม่ใช่การปรับแต่ง

### โปรโตคอล flip — จุดที่พังแล้วเปิดสถานะสวนกัน

flip คือสองขาในแท่งเดียว **ห้ามสลับลำดับ ห้ามยิงขนานกัน**

```
ขา 1  ปิดฝั่งเดิม (reduceOnly)
        │
        ├─ fill ครบ ──▶ ขา 2  เปิดฝั่งใหม่
        │
        └─ ไม่ fill ครบ ──▶ ยกเลิกขา 2 ทั้งหมด
                            เขียน DecisionRecord ด้วย skip_reason = flip_aborted
                            จบรอบ ไม่แตะ symbol นี้อีกจนแท่งถัดไป
```

เหตุผลที่ต้อง abort ไม่ใช่ retry: ถ้าขา 1 ปิดได้ไม่หมดแล้วขา 2 เดินต่อ ระบบจะเปิดสถานะสวนกับของเดิมที่ยังค้างอยู่ ซึ่งละเมิด one-way โดยตรง และบน perp มันคือการถือความเสี่ยงสองทางพร้อมกันโดยที่ไม่มีชั้นไหนตั้งใจให้เกิด

#### ของที่ค้างหลัง abort — ระบบไม่จัดการเอง คนต้องปิด

ส่วนที่ปิดไม่ลงยังเป็นสถานะเปิดอยู่ที่ exchange และ **ระบบจะไม่พยายามปิดมันเองในรอบถัดไป**

เส้นทางออกตามปกติของมันคือสัญญาณฝั่งตรงข้ามครั้งถัดไป ซึ่งเพิ่งเกิดไปแล้วในแท่งนี้และจะไม่เกิดซ้ำจนกว่าเทรนด์จะกลับอีกรอบ — อาจเป็นเดือน ระหว่างนั้นมันคือไม้ที่มี leverage และไม่มี stop

**นี่เป็นความเสี่ยงที่รับไว้อย่างรู้ตัว** ทางแก้อัตโนมัติทุกทาง (รีไทร์การปิดทุกแท่ง หรือวาง stop ให้ส่วนที่เหลือ) ทำให้ระบบมีเส้นทางที่ยิงคำสั่งนอกจังหวะสัญญาณ ซึ่งเปิดพื้นที่ให้บั๊กในโหมดที่ทดสอบยากที่สุด — ดู [decisions #19](../decisions.md)

ข้อแลกเปลี่ยนคือระบบ **ต้องทำให้ของที่ค้างมองเห็นได้ทันที** ไม่งั้น "ให้คนไปปิดเอง" แปลว่าไม่มีใครรู้ว่าต้องปิด:

- `DecisionRecord` ของแท่งนั้นต้องบันทึก `residual_qty` และฝั่งของมัน ([07](07-data-and-config.md))
- ทุกรอบถัดไปที่อ่านสถานะจริงจากปลายทาง (ขั้น 3 ของ [08](08-runtime-pipeline.md)) แล้วเจอสถานะที่ระบบไม่ได้ตั้งใจถือ ต้องบันทึกซ้ำทุกแท่ง ไม่ใช่บันทึกครั้งเดียวตอนเกิด
- คอนโซลต้องแสดงเป็นสถานะที่ต้องคนจัดการ ไม่ใช่กลืนไปกับไม้ปกติ

คนปิดผ่าน **ปิดไม้ฉุกเฉิน** ซึ่งเป็นสิทธิ์ที่มีอยู่แล้วใน [06](06-risk-and-execution.md) ไม่ต้องเพิ่มปุ่มใหม่

### ลำดับความสำคัญ

ในหนึ่งรอบการทำงาน **การออกต้องถูกประเมินก่อนการเข้าเสมอ** ต่อให้มีสัญญาณอื่นเกิดพร้อมกัน เหตุผลคือถ้าลำดับกลับกัน จะมีจังหวะที่ระบบถือสถานะเกินเพดานที่ risk limit อนุญาต

## กฎไม้เรียว (Cane Rule)

> "นักเรียนทุกคนต้องเข้าซื้อที่แท่งเขียวแรกสุดเท่านั้น หากเห็นราคาพุ่งสูงไปแล้วหลายวัน ห้ามเข้าซื้อเด็ดขาด"

เหตุผลเชิงเทคนิคที่เอกสารให้ไว้: เข้าช้าแล้วจุดตัดขาดทุนอยู่ไกลเกินไป ความเสี่ยงต่อไม้จึงโตขึ้นโดยที่ขนาดไม้เท่าเดิม บน perp ที่มี leverage ข้อนี้ยิ่งหนักขึ้น เพราะจุดตัดที่ไกลกว่าแปลว่าใกล้ราคา liquidation กว่า

**การบังคับใช้:** ถ้าแท่งปัจจุบันไม่ใช่จุดที่เกิดสัญญาณของฝั่งที่จะเข้า → ปฏิเสธการเข้า **บังคับทั้งสองฝั่งเท่ากัน** ไม่มีข้อยกเว้น ไม่มี config ให้ปิด

ข้อยกเว้นเดียวของทั้งระบบคือเส้นทาง cold start ด้านล่าง ซึ่งมีเงื่อนไขล้อมแน่นและมี stop บังคับ

## เมื่อ "ตกรถ" — cold start

บอทที่รันต่อเนื่องจะเห็นทุกสัญญาณตอนแท่งปิด **มันตกรถไม่ได้** เส้นทางนี้จึงมีไว้สำหรับสถานการณ์เดียว: engine เพิ่งเริ่มทำงานขณะที่เทรนด์เดินไปแล้ว

- `state = BULLISH` แต่แท่งล่าสุดไม่ใช่จุดสัญญาณ → ตกรถฝั่ง **long**
- `state = BEARISH` แต่แท่งล่าสุดไม่ใช่จุดสัญญาณ → ตกรถฝั่ง **short**

### เกิดใหม่ทุกครั้งที่ start engine

คอนโซลมีปุ่ม start engine กดกี่ครั้งก็ได้ **ทุกครั้งที่ engine เริ่มคือ cold start ครั้งใหม่** ไม่ใช่ของครั้งเดียวตอน boot

**ห้ามเก็บ flag `cold_start_done` ลงดิสก์** ถ้าเก็บ เส้นทางนี้จะถูกปิดถาวรหลังการ boot ครั้งแรก ทั้งที่มันควรทำงานได้อีกในรอบการรันถัดไป

### เงื่อนไขบังคับ

เส้นทางนี้ทำงานได้ก็ต่อเมื่อ **ไม่มีสถานะเปิดของ symbol นั้นที่ exchange ทั้งสองฝั่ง**

ถ้ามีอยู่แล้ว แปลว่าเคยเข้าไม้ไปก่อน restart — ให้กลับเข้าโหมดปกติคือเฝ้ารอสัญญาณฝั่งตรงข้าม ไม่ใช่เข้าไม้ซ้ำและไม่เปิดสวนสถานะเดิม นี่คือตัวกันของจริงเพียงตัวเดียวที่ทำให้การกด start engine ซ้ำๆ ระหว่างเทรนด์ไม่กลายเป็นการเพิ่มสถานะซ้อนทุกครั้ง

### การเลือกเส้นทาง

อ่านจาก config `cold_start = "wait_1h" | "trailing" | "skip"`

**ไม่ระบุ = ไม่เข้าเส้นทางนี้** (fail-closed) เมื่อถึงเฟสคอนโซลค่อยเปลี่ยนเป็นให้คนเลือกในหน้าจอ — เป็นหนึ่งในสองอย่างที่คนกดได้ (ดู [06](06-risk-and-execution.md))

### ขนาดไม้

ใช้ `base_pct` เพราะไม่ใช่แท่งสัญญาณ จึงไม่มีปัจจัยสนับสนุนให้ตัดสิน — ตรงกับกรณี "สัญญาณพื้นฐานที่ไม่มีปัจจัยสนับสนุน" ในตารางของเอกสารต้นทาง

### ทางที่ 1 — `wait_1h` ลง timeframe เล็ก

ไปดูกราฟ 1 ชั่วโมง รอสัญญาณของ timeframe นั้นแล้วเข้าด้วยความเสี่ยงที่จำกัดกว่า
ใช้ตรรกะ Action Zone ตัวเดิมทั้งหมด เปลี่ยนแค่ timeframe

### ทางที่ 2 — `trailing` CDC ATR Trailing Stop

เข้าที่ราคาปัจจุบันได้ แต่**บังคับตั้งจุดตัดขาดทุนที่เส้น Slow Trail ทันที** และเป้ากำไรต้องเป็นอย่างน้อย **2 เท่าของความเสี่ยง (RR ≥ 2:1)** ถ้า RR ไม่ถึง 2:1 ที่ราคาปัจจุบัน → ไม่เข้า

สูตรอยู่ที่ `reference/cdc_trailing_stop.pine` — *CDC ATR Trailing Stop V2.1 (2013)*

```
SL1    = 0.5 × atr(5)                    # fast
SL2    = 2.0 × atr(10)                   # slow  ← เส้นที่ใช้ตั้ง stop
Trail2 = ถ้า SC > Trail2[1] และ SC[1] > Trail2[1]  →  max(Trail2[1], SC − SL2)
         ถ้า SC < Trail2[1] และ SC[1] < Trail2[1]  →  min(Trail2[1], SC + SL2)
         ถ้า SC > Trail2[1]                        →  SC − SL2
         มิฉะนั้น                                   →  SC + SL2
Hst    = Trail1 − Trail2
Sig    = ema(Hst, 9)
```

> ⚠️ **สูตรเป็น recursive** (`Trail2` อ้าง `Trail2[1]`, seed ด้วย `nz(…, 0)`) — ต้อง port เป็น loop ไม่ใช่ vectorized

**stop อยู่ที่ exchange ไม่ใช่ที่ engine**

วาง stop order จริงไว้ที่ exchange ทันทีที่เปิดไม้ และ **เลื่อนตามเส้น Slow Trail ทุกแท่ง** (cancel/replace)

เหตุผล: ถ้าประเมิน stop ฝั่ง engine ตอนแท่งรายวันปิดอย่างเดียว บน perp ที่มี leverage ราคากระโดดข้ามคืนเดียวก็ถึง liquidation ได้ก่อนที่ engine จะตื่นมาดู — การป้องกันที่ตรวจวันละครั้งบางเกินไปสำหรับตลาดนี้ Broker interface จึงต้องรองรับ order type และการ replace ดู [06](06-risk-and-execution.md)

## สิ่งที่ระบบไม่ทำ

- **ไม่เข้าไม้เพิ่มระหว่างถือ (no pyramiding)** — เอกสารพูดถึงขนาดไม้ ณ จุดเข้า ไม่ได้พูดถึงการทยอยเพิ่ม
- **ไม่ถือสองฝั่งพร้อมกัน** — one-way ต่อ symbol เสมอ
- **ไม่มี take-profit แยกต่างหากในเส้นทางปกติ** — ออกที่สัญญาณฝั่งตรงข้ามอย่างเดียว
- **ไม่มี stop loss ในเส้นทางปกติ** — ข้อยกเว้นเดียวคือ stop ของ cold start ทางที่ 2 ที่เอกสารต้นทางบังคับไว้เอง
