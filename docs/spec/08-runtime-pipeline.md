# 08 · ลำดับการทำงาน

ทำงานเมื่อแท่งปิด ต่อหนึ่ง symbol ต่อหนึ่ง profile

```

       ข้าม symbol ที่ enabled = false หรือมีแท่งปิดน้อยกว่า 85 แท่ง
       │
 2  คำนวณ Action Zone → zone, longcond, shortcond, state, long_signal, short_signal
       │

       │              └─yes─▶  ขา 1: ปิดด้วย reduceOnly (leg = close)
       │                              │
```

## กฎที่ห้ามผิดลำดับ

**ขา 1 (ปิด) ก่อนขา 2 (เปิด) เสมอ** ถ้าสลับ จะมีจังหวะที่ระบบถือสองฝั่งพร้อมกัน ซึ่งละเมิด one-way โดยตรง และบน perp คือการถือความเสี่ยงสองทางที่ไม่มีชั้นไหนตั้งใจให้เกิด

**ขา 1 ไม่ fill ครบ = ยกเลิกขา 2 ทั้งหมด** ไม่ retry ไม่เปิดบางส่วน — บันทึก `flip_aborted` พร้อม `residual_qty` แล้วจบรอบ

ของที่ค้างจากการ abort **ระบบไม่ปิดให้เอง** (decisions #19) แต่ขั้น 3 ของทุกแท่งถัดไปจะเจอมันเพราะอ่านสถานะจริงจากปลายทาง — เจอเมื่อไหร่ให้บันทึกว่ามีสถานะที่ระบบไม่ได้ตั้งใจถือ **ซ้ำทุกแท่ง** จนกว่าคนจะปิด ไม่ใช่บันทึกครั้งเดียวตอนเกิดแล้วเงียบไป

**ขั้น 3 อ่านจากปลายทางจริง** ทั้ง position และ open order ไม่ใช่จากสถานะที่จำไว้ในหน่วยความจำ และต้องอยู่**ก่อน**ทุกการตัดสินใจ ไม่ใช่ก่อนการส่งออเดอร์เท่านั้น

**ย่อกับปฏิเสธอยู่คนละขั้นโดยเจตนา** เพดานต่อไม้ (`max_position_pct_<side>`) เป็นการ**ย่อขนาด**
จึงอยู่ในขั้น 10 คู่กับสูตร แล้วบันทึก `capped: true` ส่วนขั้น 12 ทุกข้อคือ**ปฏิเสธทั้งไม้**
ถ้าเอาเพดานไปไว้ขั้น 12 ปนกับพวกนั้น จะกลายเป็นการข้ามสัญญาณทิ้งทั้งที่ควรแค่ลงไม้เล็กลง

`max_leverage` ไม่อยู่ในขั้นนี้ — มันถูกตรวจตั้งแต่ตอนโหลด config (`leverage` ของ symbol ใด
เกินค่านี้ = โหลดไม่ผ่าน) ตอนรันจึงไม่มีทางเกินได้ สิ่งที่ต้องทำแทนคือ **ตั้ง leverage ที่
exchange ให้ตรงกับ config ก่อนเปิดไม้** (`set_leverage` ใน [06](06-risk-and-execution.md))
เพราะค่าที่ exchange ถูกเปลี่ยนจากนอกระบบได้

**ขั้น 14 เกิดทุกเส้นทาง** รวมถึงเส้นทางที่จบด้วย "ไม่ทำอะไร", เส้นทางที่ถูก risk ปฏิเสธ และเส้นทางที่ flip พัง ถ้าเขียนเฉพาะตอนมีออเดอร์ บันทึกจะกลายเป็นบันทึกที่เข้าข้างตัวเอง — เห็นแต่ตอนที่ระบบทำอะไร ไม่เห็นตอนที่มันเลือกจะไม่ทำ

## การเลื่อน stop ตาม Slow Trail

สำหรับไม้ที่เปิดด้วย cold start ทางที่ 2 เท่านั้น ทำทุกแท่งก่อนเข้าขั้น 4:

```
คำนวณ Trail2 ของแท่งที่เพิ่งปิด
   └─ ต่างจาก stop_px ที่วางไว้?  ──▶  replace(stop_order_id, Trail2)
```

ทำแม้ขณะ kill switch latch อยู่ — เป็นการขยับจุดป้องกัน ไม่ใช่การเปิดความเสี่ยงใหม่ ดู [06](06-risk-and-execution.md)

ถ้า `open_orders()` ในขั้น 3 ไม่เจอ stop order ที่ควรมี แปลว่า stop ทำงานไปแล้วหรือหลุดไป — ต้องเทียบกับ `positions()` แล้วบันทึกให้ชัด ไม่ใช่วาง stop ใหม่เงียบๆ ทับ

## cold start

เข้าเส้นทางนี้เมื่อ **ทุกข้อต่อไปนี้จริงพร้อมกัน**:

- `state` เป็น `BULLISH` หรือ `BEARISH` (ไม่ใช่ `UNSET`)
- แท่งล่าสุดไม่ใช่จุดสัญญาณ
- **ไม่มีสถานะเปิดของ symbol นั้นที่ exchange ทั้งสองฝั่ง**
- `cold_start` ใน config ระบุไว้และไม่ใช่ `skip`

ถ้าเข้าเงื่อนไข ให้แทนขั้น 6–13 ด้วยเส้นทางของ [03](03-trading-rules.md) โดยใช้ `base_pct` เป็นขนาดไม้

**เส้นทางนี้ถูกประเมินใหม่ทุกครั้งที่ engine เริ่มทำงาน** ไม่ใช่ครั้งเดียวตอน boot แรกแล้วปิดถาวร — คอนโซลกด start engine ได้ไม่จำกัดครั้ง ตัวกันการเข้าไม้ซ้ำคือเงื่อนไข "ไม่มีสถานะเปิดที่ exchange" เท่านั้น ห้ามใช้ flag บนดิสก์
