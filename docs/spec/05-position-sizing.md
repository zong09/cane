# 05 · ขนาดหน้าตัก

> "ความแตกต่างระหว่างพอร์ตที่เติบโตกับพอร์ตที่ล้มเหลว ไม่ได้อยู่ที่ใครหาจุดซื้อเก่งกว่ากัน แต่อยู่ที่ขนาดของการเข้าซื้อในตำแหน่งที่มีความได้เปรียบสูง"

## ฐานการคิด

ขนาดไม้เป็น **% ของ bucket ของ symbol นั้น ฝั่งนั้น** ไม่ใช่ % ของ equity รวมทั้งพอร์ต

แต่ละ symbol มีเงินจัดสรรของตัวเองแยกสองฝั่ง (`bucket_quote_long` / `bucket_quote_short`) การคิดแบบนี้ทำให้สอง symbol แย่งเงินก้อนเดียวกันไม่ได้ และไม่ต้องมีกฎพิเศษกันสัดส่วนรวมเกิน 100%

แลกกันตรงที่เงินที่ฝั่งหนึ่งไม่ได้ใช้จะไม่ถูกยืมไปใช้อีกฝั่ง — ตั้งใจแลกประสิทธิภาพการใช้เงินกับความง่ายในการให้เหตุผล

## สูตร

```
size_pct = min(base_pct + 20 × จำนวน factor ที่ present, 100)
size_pct = min(size_pct, max_position_pct_<side>)      ← เพดานแยกฝั่ง
margin   = bucket_quote_<side> × size_pct / 100
notional = margin × leverage
qty      = notional / ราคาอ้างอิง    แล้วปัดตาม lot size / precision
```

`<side>` คือฝั่งของไม้ที่กำลังจะเปิด — ทุกตัวในสูตรมาจากฝั่งเดียวกันหมด ห้ามผสม

**ปัดลงเสมอ** — ปัดขึ้นแปลว่าเกินเพดานที่ตั้งไว้

| ปัจจัย | ผล |
| --- | --- |
| สัญญาณพื้นฐาน ไม่มีปัจจัยสนับสนุน | `base_pct` |
| factor ที่ 1 ของฝั่งนั้น | +20 |
| factor ที่ 2 | +20 |
| factor ที่ 3 | +20 |
| ครบทุกปัจจัย | `base_pct + 60` → **65** ที่ `base_pct = 5` |

## ตัวเลข 80–100 ในเอกสารต้นทาง — ตัดสินแล้ว

เอกสารต้นทาง §3 ระบุไม้พื้นฐานไว้ 5–20% และปัจจัยละ +20% สามตัว แต่บรรทัดสุดท้าย ("พอร์ตฟอร์มสมบูรณ์แบบสูงสุด") เขียนว่า 80–100% ซึ่งบวกจริงแล้วไม่ถึง — ได้แค่ 65 (ที่ `base_pct = 5`) ถึง 80 (ที่ `base_pct = 20`)

**เจ้าของระบบตัดสินแล้ว: ยอมรับช่วง 65–80 ใช้สูตรบวกตรงๆ และตั้ง `base_pct = 5`**

ถือว่าตัวเลข 80–100 ในเอกสารต้นทางเป็นการพูดโดยประมาณ ไม่ใช่กฎ ทางเลือกอื่นที่ปฏิเสธไป:

- **ตั้ง `base_pct = 20`** เพื่อให้ครบทุกปัจจัยได้ 80 — ทำให้ไม้พื้นฐานกลายเป็น 20% ซึ่งขัดกับเจตนา "ลงปริมาณน้อยที่สุดเพื่อทดลองแนวโน้ม"
- **ให้กรณีครบทุกปัจจัยกระโดดไปที่ 100** เป็นกรณีพิเศษ — ทำให้สูตรมีข้อยกเว้นที่อธิบายด้วยหลักการไม่ได้

ทางที่เลือกเป็นทางที่อนุรักษ์นิยมที่สุดด้านขนาดไม้ ซึ่งสำคัญขึ้นอีกเมื่อระบบมี leverage

## `base_pct` ต้องเป็นค่าคงที่

เอกสารต้นทางให้ช่วง 5–20% สำหรับไม้พื้นฐาน ระบบนี้กำหนดให้เป็น **ค่าคงที่ใน config** (ค่าตั้งต้น 5) และตรวจว่าอยู่ในช่วง 5–20 ตอนโหลด

**ห้ามผูกกับ `confidence` ของ LLM** ถ้าผูก ขนาดไม้จะแกว่งตามความมั่นใจที่เป็นตัวเลขนุ่มๆ ซึ่งลบล้างเจตนาของการ cache verdict ไปทั้งหมด — เราอุตส่าห์บังคับให้ LLM ตอบเหมือนเดิมทุกครั้งแล้ว ไม่ควรเปิดช่องให้ความไม่แน่นอนกลับเข้ามาทางประตูหลัง

`confidence` ใช้สำหรับให้คนอ่านย้อนหลังและสำหรับการวิเคราะห์ในอนาคตเท่านั้น

## leverage อยู่ตรงไหนของสูตร

`leverage` คูณที่ **notional ไม่ใช่ที่ `size_pct`**

ผลคือขนาดของ *ความเสี่ยงต่อเงินทุน* ยังถูกคุมด้วย `size_pct` และ bucket เหมือนเดิม ส่วน `leverage` เปลี่ยนแค่ว่ามูลค่าสัญญาที่ถือใหญ่แค่ไหนเทียบกับ margin ที่วาง ถ้าเอา `leverage` ไปคูณที่ `size_pct` เพดาน `max_position_pct_<side>` จะไม่มีความหมายอีกต่อไป

`leverage` ที่เกิน `max_leverage` ทำให้ config โหลดไม่ผ่านตั้งแต่แรก ([07](07-data-and-config.md)) และไม้ที่คำนวณแล้วมีระยะถึงราคา liquidation น้อยกว่า `min_liq_buffer_pct` จะถูกปฏิเสธที่ชั้น risk ([06](06-risk-and-execution.md)) — ไม่ใช่ถูกย่อขนาดลงให้พอดี

## เพดานทับ

`risk.max_position_pct_long` / `max_position_pct_short` ทับผลจากสูตรนี้ได้เสมอ ถ้าสูตรบอก 65 แต่เพดานตั้งไว้ 50 ให้ใช้ 50 และ **บันทึก `capped: true` ลง DecisionRecord** เพื่อให้ตอนอ่านย้อนหลังแยกออกว่าไม้เล็กเพราะปัจจัยน้อย หรือเพราะชนเพดาน

## ขนาดไม้ของเส้นทาง cold start

ใช้ `base_pct` ตรงๆ ไม่เรียก Judge — ไม่ใช่แท่งสัญญาณจึงไม่มีปัจจัยสนับสนุนให้ตัดสิน ดู [03](03-trading-rules.md)
