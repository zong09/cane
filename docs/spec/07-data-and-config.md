# 07 · ข้อมูลและการตั้งค่า

## แหล่งข้อมูลราคา

ccxt ต่อ Binance ดึง OHLCV รายวันเป็นหลัก และราย 1 ชั่วโมงสำหรับเส้นทาง cold start ทางที่ 1

**ดึงเฉพาะแท่งที่ปิดแล้ว** — แท่งล่าสุดที่ยังวิ่งอยู่ต้องถูกตัดทิ้งเสมอ ไม่ใช่เพราะความประณีต แต่เพราะสีของ Action Zone เปลี่ยนไปมาได้ตลอดวันจนกว่าแท่งจะปิด ถ้าไม่ตัด ระบบจะเห็น "เขียวแรก" ที่หายไปตอนบ่าย

cache ลงดิสก์เพื่อไม่ให้ยิงซ้ำ ข้อมูลแท่งที่ปิดแล้วไม่เปลี่ยน จึง cache ได้ปลอดภัย

## funding rate

perp มีค่า funding ทุก 8 ชั่วโมง ซึ่งเป็น **ต้นทุนจริงของการถือไม้ข้ามรอบ** ไม่ใช่ตัวเลขประกอบ

- ดึง funding rate ปัจจุบันต่อ symbol — คอนโซลแสดงคู่กับ leverage และระยะถึง liquidation
- เก็บ funding ที่**เกิดขึ้นจริง**ต่อไม้ลง trade ledger เพื่อให้รายงานคิดต้นทุนรวมได้ถูก
- funding **ไม่เข้าสูตรขนาดไม้** ([05](05-position-sizing.md)) — มันเกิดหลังเปิดไม้แล้ว การเอามาปรับขนาดไม้จะทำให้สัญญาณเดียวกันให้ผลต่างกันตามเวลาที่รัน ซึ่งขัดกับหลักความคงเส้นคงวา

ดึงไม่ได้ = บันทึกว่าไม่มีข้อมูล **ไม่ใช่เดาเป็น 0** ต้นทุนที่หายไปเงียบๆ ทำให้รายงานสวยกว่าความจริง

**symbol ที่มีแท่งปิดน้อยกว่า 85 แท่ง ให้ข้ามทั้งรอบ** — ไม่คำนวณ ไม่ตัดสิน ดู [02](02-action-zone.md) เรื่อง warm-up สองตัวเลข

## Config profile

**แหล่งความจริงของ config คือตารางใน PostgreSQL** ([decisions #18](../decisions.md)) ไฟล์ TOML
เหลือหน้าที่เดียวคือเป็นทางเข้าครั้งแรกผ่าน `cane db seed --profile X --from config/X.toml`

สอง profile โครงเดียวกัน โค้ดเส้นทางเดียวกัน ต่างกันแค่ค่า — **คนละชุดแถว ไม่ใช่คนละไฟล์**:

- profile `paper` — `broker.kind = "paper"`, `dry_run` บังคับ `true`
- profile `live` — `broker.kind = "ccxt"` และ `dry_run = true` เป็นค่าตั้งต้น

**ทุกการแก้สร้างเวอร์ชันใหม่ ไม่ทับของเก่า** และเวอร์ชันเก่าอ่านได้ตลอดไป · เวอร์ชันที่ระบบใช้อยู่
ชี้ด้วย `is_active` ซึ่ง active ได้ profile ละหนึ่งเวอร์ชันเท่านั้น (บังคับด้วย partial unique index)
· **ไม่มีเวอร์ชัน active = ไม่เทรด** ไม่ใช่ถอยไปใช้ค่าตั้งต้น

ตารางที่ถือค่าเหล่านี้: `config_versions` (หัว) + `config_settings` · `config_symbols` ·
`config_risk` · `config_broker` · `config_data` · รูปร่างจริงอ่านได้จาก `src/cane/db/schema.py`

รูปของไฟล์ seed (และของฟอร์มในคอนโซล ซึ่งเป็นค่าชุดเดียวกัน):

```toml
profile    = "live"           # live | paper
market     = "usdtm_perp"
timeframe  = "1d"
cold_start = "wait_1h"        # wait_1h | trailing | skip — ไม่ระบุ = ไม่เข้าเส้นทาง cold start
base_pct   = 5.0              # ต้องอยู่ 5–20
dry_run    = true
allow_short = true            # สวิตช์ระดับระบบ — false = ปิดฝั่ง short ทุกเหรียญ

[[symbols]]
symbol             = "BTC/USDT"
bucket_quote_long  = 100.0
bucket_quote_short = 60.0     # เว้นได้ = เทรดฝั่ง long อย่างเดียว
leverage           = 2.0
allow_short        = true
enabled            = true     # false = พักไว้ คงบล็อกไว้แต่ข้ามในรอบคำนวณ

[risk]
max_position_pct_long    = 50.0
max_position_pct_short   = 40.0
max_leverage             = 3.0
min_liq_buffer_pct       = 25.0
max_daily_loss_pct       = 3.0
consecutive_loss_breaker = 2

[broker]
kind          = "ccxt"        # ccxt | paper
exchange      = "binance"     # บังคับเมื่อ kind = ccxt
margin_mode   = "isolated"
position_mode = "one_way"
# paper เท่านั้น: seed_quote = 10000.0

[data]
exchange = "binance"
```

`timeframe` อยู่ระดับบนสุดตัวเดียวในเฟสแรก ถ้าจะรองรับรายเหรียญทีหลัง ให้เพิ่มเป็นคอลัมน์ override
ใน `config_symbols` ไม่ใช่ย้ายที่

## กฎการตรวจ config

**บันทึกเวอร์ชันไม่ผ่าน** (ไม่ใช่เตือนแล้วไปต่อ) เมื่อ — และค่าชุดที่ไม่ผ่านต้องไม่ลง DB เลย
ไม่ใช่ลงแล้วไม่ activate:

- ขาด risk limit ตัวใดตัวหนึ่ง — ไม่มี default ให้
- มีคีย์ที่ไม่รู้จัก เช่นพิมพ์ `max_daily_loss_pcnt` ผิด — ป้องกันการตั้งค่าที่หายไปเงียบๆ
- `base_pct` อยู่นอกช่วง 5–20
- **`leverage` ของ symbol ใดเกิน `max_leverage`**
- `allow_short = true` ของ symbol ใด แต่ไม่มี `bucket_quote_short`
- `broker.kind = "ccxt"` แต่ไม่ระบุ `exchange`
- `broker.kind` ไม่ใช่ `paper` แต่มี `seed_quote` — เงินตั้งต้นจำลองไม่มีความหมายกับ broker จริง
- `position_mode` ไม่ใช่ `one_way` — **`hedge` ไม่ใช่ตัวเลือกที่ปิดไว้ แต่เป็นค่าที่ระบบไม่รองรับ** เพราะมันทำให้ถือสวนกันในคู่เดียวได้ ซึ่งละเมิดหลัก "หนึ่งฝั่งต่อเหรียญเสมอ" ([03](03-trading-rules.md))
- ค่าที่ต้องเป็นบวกแต่ไม่เป็น — `bucket_quote_*`, `leverage`, risk limit ทุกตัว · เปอร์เซ็นต์ที่เกิน 100
- ไม่มี symbol เลย
- **ค่าที่ละเอียดกว่าที่เก็บได้** — เปอร์เซ็นต์และตัวคูณเก็บได้ 4 ทศนิยม เงินเก็บได้ 8 ทศนิยม
  ค่าที่ละเอียดกว่านั้นต้อง **ปฏิเสธ ไม่ใช่ปัดให้** เพราะการปัดที่ไม่มีใครเห็นทำให้ระบบเทรดด้วย
  ค่าที่ไม่ใช่ค่าที่คนกรอก

`dry_run` ที่ไม่ระบุ ให้เป็น `true` · profile `paper` ที่ตั้ง `dry_run = false` ให้ **บันทึกไม่ผ่าน** ไม่ใช่แก้ให้เงียบๆ

**กฎเกือบทุกข้อข้างบนซ้ำอยู่ใน `CHECK` ของ schema ด้วย และซ้ำโดยเจตนา** — `CHECK` เป็นด่านสุดท้าย
ที่ทับไม่ได้ แต่มัน **ล้มที่ข้อแรกที่เจอเสมอ** จึงบอกได้ทีละข้อ · validator มีไว้เพื่อบอกให้ครบทุกข้อ
ในรอบเดียว · ข้อเดียวที่อยู่ที่ validator เท่านั้นคือ **`leverage` ของ symbol เทียบกับ `max_leverage`**
เพราะเป็นกฎข้ามตาราง ซึ่ง SQL เขียนเป็น `CHECK` ไม่ได้

### `allow_short` มีสองชั้น

ระดับบนสุดเป็นสวิตช์ของทั้งระบบ ระดับ `[[symbols]]` เป็นของเหรียญนั้น **ผลจริงคือ AND ของทั้งสองชั้น** — ปิดข้างบนแล้วเปิดรายเหรียญไว้ก็ยังปิด

ตั้งใจให้ปิดข้างบนได้ทีเดียวโดยไม่ต้องไล่แก้ทุกบล็อก เพราะเป็นการกระทำที่มักเกิดตอนรีบ ปิดแล้วระบบยัง **ปิดไม้ตามสัญญาณฝั่งตรงข้ามเสมอ** ไม่ใช่หยุดทำอะไรเลย ([03](03-trading-rules.md))

**ตรวจให้ครบทุกข้อก่อนแล้วค่อยปฏิเสธ** ไม่ใช่หยุดที่ข้อแรก คนแก้ต้องเห็นรายการทั้งหมดในรอบเดียว ไม่ใช่แก้ทีละข้อแล้วกดบันทึกใหม่ทุกครั้ง

## path ของฟิลด์ที่ผิด

**validator ต้องคืน path ของฟิลด์ของทุกข้อผิดพลาด** ไม่ใช่แค่ข้อความ — คอนโซลเอาไปชี้ช่องกรอกที่ต้องแก้

รูปของ path ตรงกับชื่อ input ในฟอร์ม: `base_pct` · `risk.max_leverage` · `symbols[0].leverage`

| กรณี | ชี้ที่ |
| --- | --- |
| ค่าผิด หรือคีย์ที่ไม่รู้จัก | ฟิลด์นั้นเอง |
| คีย์ที่หายไป | ฟิลด์ที่ควรมีค่า (`risk.consecutive_loss_breaker`) |
| กฎที่ข้ามหลายคีย์ | ฟิลด์ที่**จุดชนวน**กฎ ไม่ใช่ฟิลด์ที่หาย |
| ไฟล์ seed ผิดไวยากรณ์ TOML | ไม่มีฟิลด์ให้ชี้ — `loc` ว่าง และข้อความพาเลขบรรทัดของ `tomllib` ไปด้วย |

ข้อที่สามจำเป็นเพราะฟิลด์ที่หายไม่มีค่าให้คนเห็น เช่น `kind = "ccxt"` โดยไม่มี `exchange`
ต้องชี้ที่ `broker.kind`

> **เดิมข้อนี้เป็นเลขบรรทัด (`L4 / L19`)** ตอนที่ config อยู่ในไฟล์ TOML · ไม่มีไฟล์ก็ไม่มีบรรทัดให้ชี้
> และหน้าตั้งค่าก็ไม่ใช่ตัวแก้ไฟล์อีกแล้ว แต่เป็นฟอร์มต่อฟิลด์ — path ของฟิลด์จึงตรงกับสิ่งที่หน้าจอ
> ต้องใช้มากกว่าที่เลขบรรทัดเคยเป็น (mockup ของ design ที่ติด badge `L…` ไว้ ใช้อ้างอิงไม่ได้แล้ว)

การพิมพ์คีย์ผิดหนึ่งครั้งให้สองข้อเสมอ — "คีย์ที่ไม่รู้จัก" ที่ฟิลด์ที่พิมพ์ผิด และ "ขาดคีย์จริง" ที่ฟิลด์ที่ควรมี ทั้งคู่จริงทั้งคู่ ตัวตรวจจึงควรเดาคำที่ใกล้เคียงแนบไปกับข้อแรกเพื่อโยงสองข้อเข้าด้วยกัน

## บันทึกการตัดสินใจ

`DecisionRecord` เป็น JSONL แบบ append-only หนึ่งบรรทัดต่อหนึ่งแท่งต่อหนึ่ง symbol เขียน **ทุกกรณี** รวมถึงตอนที่ผลลัพธ์คือ "ไม่ทำอะไร"

```
ts · symbol · zone · signal · side
flip { close_qty_intended, close_qty_filled, residual_qty, aborted }
leverage · margin_mode
verdicts[]        พร้อมธงว่ามาจาก cache หรือ fallback
size_rule · size_pct_formula · size_pct_final · capped
margin · notional · qty
stop { px, order_id }        เส้นทาง cold start ทางที่ 2 เท่านั้น
risk              ผลการตรวจทีละชั้น
order             ที่ส่งจริง หรือ
skip_reason       เหตุผลที่ไม่ส่ง เช่น flip_aborted, cane_rule, kill_switch, liq_buffer
unmanaged         สถานะที่เปิดค้างอยู่ที่ปลายทางแต่ระบบไม่ได้ตั้งใจถือ — เขียนซ้ำทุกแท่ง
                  จนกว่าคนจะปิด (มาจาก flip_aborted, decisions #19)
```

นี่คือสิ่งที่ทำให้ backtest ย้อนหลังได้ในภายหลังโดยไม่ต้องรื้อระบบ ระบบเฟสแรกไม่มี backtest engine แต่ต้องไม่ปิดประตูตัวเอง

รายงาน "ไม้ที่ปิดแล้ว" derive จาก DecisionRecord อย่างเดียวไม่ได้ — ต้องมี trade ledger แยกที่เก็บ fill จริงของขาเข้า/ขาออก, fee, funding, slippage และ `exit_reason` ต่อไม้

## ความปลอดภัยของ credential

- API key อยู่ใน environment / ไฟล์ `.env` ที่คนกรอกเอง
- `.env` อยู่ใน `.gitignore` ตั้งแต่ commit แรก
- profile `paper` **ไม่อ่าน API key เลย** และไม่เรียก endpoint ที่ส่งคำสั่ง
- log ผ่าน filter ที่ลบค่าของคีย์ที่มีคำว่า key / secret / token / password / passphrase และที่อยู่แบบ `0x…` ออกอัตโนมัติ
- ตั้งใจ **ไม่** ลบเลขล้วนยาวๆ ออก เพราะ epoch timestamp จะหายไปด้วย
