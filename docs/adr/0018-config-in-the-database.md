# ADR 18 · config อยู่ใน DB เป็นเวอร์ชันที่แก้ไม่ได้ · TOML เหลือหน้าที่ seed (เขียนใหม่ 2026-09-02)

**สถานะ:** accepted · **เขียนใหม่ทั้งข้อ 2026-09-02** ทับมติเดิมที่ให้ config มาจาก TOML อย่างเดียว

แหล่งความจริงของ config คือตาราง `config_versions` กับลูกห้าตารางของมัน
ไฟล์ `config/*.toml` เหลือหน้าที่เดียว: เป็นทางเข้าครั้งแรกผ่าน `cane db seed`

**ทุกการแก้สร้างเวอร์ชันใหม่ ไม่ทับของเก่า** และเวอร์ชันเก่าอ่านได้ตลอดไป
`is_active` เป็นแค่ **ตัวชี้** ว่าเวอร์ชันไหนใช้อยู่ — คอนโซลได้สิทธิ์ `UPDATE`
เฉพาะคอลัมน์นั้นคอลัมน์เดียว (grant ระดับคอลัมน์) เนื้อของเวอร์ชันแก้ไม่ได้แม้แต่คอนโซล

### ข้อนี้เดิมว่าอะไร และทำไมเปลี่ยน

เดิมข้อนี้บอกว่า "config มาจากไฟล์ TOML อย่างเดียว ไม่มีชั้น environment มาทับ" ·
**เจตนาเดิมยังอยู่ครบ** — ค่าที่ระบบใช้ต้องไม่ต่างจากค่าที่คนเห็น และไม่มีชั้นไหนมาทับ
เงียบๆ · ที่เปลี่ยนคือ *ที่เก็บ* ไม่ใช่หลักการ

เหตุผลที่ทำให้ไฟล์ไม่พอ: คอนโซลแก้ไฟล์แล้วสั่งโหลดใหม่ (มติเดิมของ 2026-09-01)
ทำให้เวลาของการแก้ผูกกับ **เวลาที่ commit** ไม่ใช่กับ `bar_close_ts` ของแท่งที่ตัดสิน
พออ่านบันทึกย้อนหลังจึงตอบไม่ได้ว่า "แท่งนี้ตัดสินด้วย `base_pct` เท่าไร" นอกจากจะเดา
จาก git log · ทางแก้เดิมคือ snapshot ค่าลงทุกแถวบันทึก ซึ่งสร้างแหล่งความจริงที่สอง
ที่ขัดกับแหล่งแรกได้ · `decisions.config_version_id` เป็น FK ตรงไปที่เวอร์ชันที่ใช้จริง
ทำให้คำถามนั้นตอบได้โดยโครงสร้าง ไม่ใช่โดยการเดา

### สิ่งที่เสียไป และยอมรับแล้ว

**การรีวิว config ผ่าน `git diff` หายไป** มติเดิมตั้งใจใช้มันเป็นร่องรอย ("การแก้ทุกครั้ง
เห็นได้ใน git diff") ตอนนี้ไม่มีหน้า diff ให้คนรีวิวก่อน merge อีกแล้ว ·
`config_versions` ที่ immutable + `created_by_user_id` + `note` แทนได้ในแง่ *ใครแก้อะไร
เมื่อไร* และดีกว่าในแง่การผูกกับเวลาของแท่ง แต่ **ไม่ใช่ของแทนที่เท่ากัน** — การกันคนแก้
พลาดต้องย้ายไปอยู่ที่ permission กับหน้าจอยืนยัน ไม่ใช่ที่ขั้นตอน review PR

### ที่ไม่เปลี่ยน

- **ไม่มีชั้น environment มาทับ config** เหมือนเดิม — env มีแค่ `CANE_DB_DSN` และ
  credential ซึ่งเป็นคนละเรื่องกับค่าของกลยุทธ์ (#25)
- **ไม่มีโหมดเตือนแล้วไปต่อ** ค่าที่ไม่ผ่านกฎบันทึกเป็นเวอร์ชันไม่ได้ และไม่มีเวอร์ชัน
  active = ไม่เทรด ([spec/07](../spec/07-data-and-config.md))
- **ไม่มีค่าตั้งต้นให้ risk limit** — เดิมคือการไม่ใส่ default ใน pydantic ตอนนี้เป็น
  `NOT NULL` ของ schema ด้วย บังคับสองชั้น
- state ของการทำงาน (kill switch, engine running, สวิตช์แจ้งเตือน) ยังแยกจาก config
  เหมือนเดิม เปลี่ยนแค่จากไฟล์ JSON ใน `var/state/` เป็นตารางของตัวเอง

### ตัวตรวจ: จาก path → เลขบรรทัด เป็น path → ฟิลด์

`validate.py` เดิมสแกนตัวอักษรดิบของไฟล์เพื่อทำแผนที่ path → เลขบรรทัด ให้คอนโซล
แสดง badge `L4 / L19` · ไม่มีไฟล์ก็ไม่มีบรรทัดให้ชี้ ตัวที่แทนคือ **path ของฟิลด์**
(`symbols[0].leverage`) ซึ่งตรงกับชื่อ input ในฟอร์มมากกว่าเลขบรรทัดอยู่แล้ว

`validate_settings()` เป็นประตูเดียวที่ค่าจากภายนอกผ่าน ไม่ว่าจะมาจากไฟล์ seed หรือ
จากฟอร์มคอนโซล — และมันยังจำเป็นแม้ DB จะมี `CHECK` ครบ เพราะ **CHECK ล้มที่ข้อแรก
ที่เจอเสมอ** ส่วนคนแก้ต้องเห็นทุกข้อในรอบเดียว · กฎที่ DB เขียนไม่ได้เลยคือ `leverage`
ต่อเหรียญเทียบกับ `max_leverage` ของ profile (กฎข้ามตาราง) จึงอยู่ที่ validator เท่านั้น
