# ADR 35 · เลือกเส้นทาง cold start ต่อเหรียญเป็นเจตนาของรอบถัดไป

**สถานะ:** proposed (2026-09-23) · **ยังไม่มีโค้ด** — `POST /api/{profile}/coldstart/{symbol}` ใน
[spec/10 §6. สัญญาของ API](../spec/10-engine-and-console.md) ติดป้ายว่ายังไม่สร้างจนกว่าข้อนี้จะ accepted

ใบ 25 สร้างแท็บ Cold start แบบอ่านอย่างเดียว · เส้นทางวันนี้มาจาก `cold_start` ของ config ซึ่ง
เป็นค่าเดียวต่อโปรไฟล์ แต่ design (§9.2c) กับ spec/10 ให้คนเลือกต่อเหรียญต่อรอบ และ spec/03
§การเลือกเส้นทาง เขียนไว้ว่า "เมื่อถึงเฟสคอนโซลค่อยเปลี่ยนเป็นให้คนเลือกในหน้าจอ"

## ข้อจำกัดที่ข้อเสนอนี้ต้องเคารพ

1. **ห้ามมีธง `cold_start_done` บนดิสก์** (spec/03 §เกิดใหม่ทุกครั้งที่ start engine) — ทุกครั้งที่
   engine เริ่มคือ cold start ครั้งใหม่
2. **engine ตัดสินแท่งแรกทันทีที่เริ่ม** — `loop.run()` เริ่มด้วย `done_close = 0` แล้ว
   `due_close()` คืนแท่งที่ปิดล่าสุดในรอบแรกเลย · ไม่มีช่วงหลัง start ให้คนเลือก
   **เจตนาจึงต้องถูกเลือกก่อนกด start** และต้องผูกกับ run ที่จะเกิด ไม่ใช่ run ที่กำลังเดิน
3. **ตัวกันจริงยังเป็น "ไม่มีสถานะเปิดทั้งสองฝั่ง"** (spec/03 §เงื่อนไขบังคับ) · เจตนาเลือกได้แค่
   *ทาง* — ไม่ข้ามประตูใดของ `late_entry()` · ทาง `trailing` ยังต้องมี stop และ RR ≥ 2:1
4. **engine อ่านได้ เขียนไม่ได้** ตาม ADR 23 — ตารางที่คอนโซลเขียนเป็น "สภาพปัจจุบัน"
   แบบเดียวกับ `kill_switch` ส่วนประวัติว่าใครเลือกอะไรอยู่ที่ `user_audit_log`

## ข้อเสนอ

ตาราง `cold_start_intent` · กุญแจ `(profile, market, symbol)` · คอลัมน์ `route`
(`wait_1h` / `trailing` / `skip`), `chosen_by`, `chosen_ts` · คอนโซล `INSERT … ON CONFLICT UPDATE`
(เลือกซ้ำค่าเดิม = no-op, เลือกค่าใหม่ = ทับ — ตามคอลัมน์ "ทำซ้ำแล้วเป็นอย่างไร" ของ spec/10)

**อายุของเจตนาผูกกับเวลาที่ run เริ่ม ไม่ใช่ธงว่าใช้แล้ว** · engine จำ `run_started_ts` ใน
หน่วยความจำ (หายพร้อม process ตามข้อ 1) และที่แท่งแรกของ run ใช้เจตนาที่
`chosen_ts < run_started_ts` และใหม่กว่า **แท่งแรกของ run ก่อนหน้า** เท่านั้น — เจตนาที่เลือกไว้
ก่อน run ที่แล้วถือว่าถูกใช้ไปแล้ว ไม่ติดค้างข้าม run · ไม่มีเจตนา = ใช้ `cold_start` ของ config
ตามเดิม · เวลาแท่งแรกของ run ก่อนหน้าอ่านได้จาก `decisions` (แถวแรกที่มี `cold_start` ไม่เป็น
`NULL` ของเหรียญนั้น) จึงไม่ต้องมีคอลัมน์ใหม่ที่ engine ต้องเขียน

แถว `decisions` ของแท่งนั้นบันทึก `cold_start` เป็นทางที่ใช้จริงอยู่แล้ว · เพิ่มแหล่งของทาง
(`config` / `intent`) ได้ถ้าต้องการให้ตรวจย้อนหลังแยกได้ว่าคนเลือกหรือ config เลือก

สิทธิ์ `choose_cold_start_route` (OWNER, TRADER) มีอยู่แล้วในตารางสิทธิ์ · ไม่ต้อง step-up
ตาม spec/09 §4. endpoint → สิทธิ์ที่ต้องมี เพราะเจตนาไม่ข้ามประตูใดของระบบ

## คำถามที่ต้องตอบก่อน accepted

- **เจตนาต่อเหรียญกับ config ต่อโปรไฟล์ อะไรชนะ** เมื่อ config เป็น `skip` แต่คนเลือก `trailing` ·
  ข้อเสนอ: เจตนาชนะ เพราะมันคือการกดของคนที่มีสิทธิ์ และ config คือค่าตั้งต้น
- **`wait_1h` ยังไม่มีใน engine** — เจตนาที่เลือกทางนี้ควรถูกปฏิเสธที่ endpoint (422) หรือรับไว้แล้ว
  บันทึกว่ารอ แบบที่ config ทำอยู่
- **คนกดเลือกระหว่างที่ engine กำลังเดิน** — ข้อเสนอข้างบนทำให้มันมีผลกับ run ถัดไป ต้องบอก
  บนหน้าจอให้ชัด ไม่งั้นคนจะเข้าใจว่ากดแล้วเข้าไม้ทันที
