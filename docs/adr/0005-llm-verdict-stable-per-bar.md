# ADR 5 · คำตัดสินของ LLM ต้องคงที่ต่อแท่ง

**สถานะ:** accepted

temperature 0 + structured output + cache ด้วย key `(symbol, timeframe, bar_close_ts, factor, prompt_hash)`

เอกสารต้นทางยืนบนหลัก "ระบบไม่เคยหลอกเรา" ระบบที่ตอบคนละอย่างสองครั้งบนข้อมูลเดิมถือว่าหลอก และเนื่องจากคำตัดสินแปลงเป็นขนาดไม้โดยตรง ความไม่คงที่จะกลายเป็นเงินจริงทันที

**แก้ถ้อยคำ 2026-09-09:** กุญแจที่เขียนไว้ข้างบน **ขาด `side`** ·
[spec/04](../spec/04-confluence-judge.md) ระบุกุญแจจริงเป็น
`(symbol, timeframe, bar_close_ts, side, factor, prompt_hash)` และให้เหตุผลไว้ว่าแท่งเดียวกัน
เป็นได้ทั้งจุดปิด long และจุดเปิด short — ถ้าไม่มี `side` คำตัดสินของสองฝั่งจะทับกันเงียบๆ
**สเปกเป็นตัวจริง** ข้อความเดิมเป็นของก่อน [ADR 15](0015-both-sides-long-and-short.md)
ที่เปิดการเทรดสองฝั่ง

**แก้ถ้อยคำ 2026-09-14:** กุญแจข้างบน **ยังขาด `market`** และ **`temperature 0` ไม่ใช่
ข้อบังคับอีกแล้ว** · กุญแจจริงตาม [spec/04](../spec/04-confluence-judge.md) คือ
`(market, symbol, timeframe, bar_close_ts, side, factor, prompt_hash)` — `market`
เข้ามาตาม [ADR 26](0026-market-is-per-symbol.md) ที่ทำให้ `BTC/USDT` บน spot
กับบน perp เป็นคนละแท่ง · ส่วน `temperature 0` ถูกแทนด้วย "ตั้งค่าการสุ่มต่ำสุด**เท่าที่
API นั้นรองรับ**" เพราะ Claude ตั้งแต่ Opus 4.7 / Sonnet 5 ถอดพารามิเตอร์นี้ออกแล้ว
(ส่งไปได้ 400) และเพราะมันไม่เคยรับประกัน determinism อยู่แล้ว — **หลักประกันเดียวคือ
cache ต่อแท่ง** ซึ่งเป็นแก่นของ ADR นี้และไม่เปลี่ยน

**เหตุผลของ `side` ที่เขียนไว้ในย่อหน้าบนไม่จริง** — ชื่อ factor ของสองฝั่งไม่ซ้ำกัน
เลยสักตัว คำตัดสินสองฝั่งจึงทับกันไม่ได้อยู่แล้ว · `side` คงไว้เพราะอยู่ใน PK คู่กับ
CHECK ที่ผูก factor↔side

**ผลตามมา:** การแก้ prompt ทำให้ cache เก่าใช้ไม่ได้ ซึ่งเป็นเจตนา · เช่นเดียวกับการ
เปลี่ยนโมเดล หรือการย้าย gateway — ทั้งสองอย่างอยู่ใน `prompt_hash` ด้วย
