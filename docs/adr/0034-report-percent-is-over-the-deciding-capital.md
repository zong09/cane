# ADR 34 · % รวมของหน้ารายงานหารด้วยทุนของเวอร์ชันที่ตัดสินไม้นั้น

**สถานะ:** accepted (2026-09-23 · ใบ 25) · **นิยามตัวเลขของหน้ารายงาน ([spec/10 §6. สัญญาของ API](../spec/10-engine-and-console.md))**

หน้ารายงานแสดง % สองแบบที่ไฟล์ design วางไว้คู่กัน: **% ต่อไม้** (`+14.2%` ในตารางไม้ที่ปิดแล้ว)
กับ **% รวม** (`+6.2%` ใน KPI, `ฝั่ง long +6.9 จุด`, equity curve) · ต่อไม้คิดบน notional ขาเข้า
ไม่มีคำถาม · ส่วนรวม design หารด้วย bucket long อย่างเดียว (`+18.55 / 300`) และไม่ได้บอกว่า
ถ้า bucket ถูกแก้ระหว่างทาง ตัวหารเป็นของวันไหน

## ตัดสิน

- **ทุน = ผลรวม `bucket_quote_long + bucket_quote_short` ของเหรียญที่เปิดใช้** — ทั้งสองฝั่ง
  เพราะ ADR 8 แยกเงินต่อฝั่งเป็นเงินคนละก้อน ไม่ใช่ก้อน long ที่ short ยืมใช้ · spot ไม่มี
  bucket short (ADR 26) นับเป็นศูนย์
- **ทุนอ่านจากเวอร์ชันที่ตัดสินเปิดไม้นั้น** (`decisions.config_version_id` ของแถวที่เปิด) ไม่ใช่
  เวอร์ชันที่ active วันนี้ · แก้ bucket วันนี้ต้องไม่เขียนผลย้อนหลังทั้งหน้าใหม่ ทั้งที่ไม่มี
  ไม้ไหนเปลี่ยน — คำถามเดียวกับที่ ADR 18 ตอบให้ `base_pct` ("ค่าไหนตัดสินแท่งนี้")
- **% รวม = `Σ net_quote ÷ ทุน`** ไม่ใช่ผลบวกของ % ต่อไม้ — % ต่อไม้คิดบน notional คนละก้อน
  ไม้ 10% บน notional 20 กับไม้ 10% บน notional 2,000 ไม่ใช่ผลเท่ากัน
- **ไม้ในช่วงที่เลือกมาจากทุนมากกว่าหนึ่งก้อน → ไม่มี % รวม** · หน้าจอแยกผลเป็นช่วงตามทุน
  (`segments`) แทน · % รวม, จุดต่อฝั่ง, ต้นทุนเป็นจุด, drawdown และ equity curve เป็น `—`
  ตามไปด้วย เพราะทั้งหมดขึ้นกับตัวหารนี้ · ยอด USDT ตอบได้เสมอ
- สองเวอร์ชันที่ทุนเท่ากันเป็นก้อนเดียวกัน — ตัวหารเท่ากันไม่มีอะไรให้แยก
- ไม้ที่หาแถวที่เปิดไม่เจอ = ไม่รู้ทุน = ก้อนของตัวเองที่ไม่มี % · ไม่หารด้วยทุนของไม้อื่นแทน

โค้ดอยู่ที่ `report.summarize()` (pure) กับ `db/repo/report.py` (`origins()`, `capital_of()`)

## ทำไมไม่ทำทางอื่น

- **หารด้วยทุนของเวอร์ชันที่ active** — ง่ายกว่า แต่ตัวเลขย้อนหลังขยับทุกครั้งที่แก้ config
  หน้าที่มีไว้ตรวจย้อนหลังจะเชื่อไม่ได้ตั้งแต่วันแรกที่มีคนแก้ bucket
- **ถ่วงน้ำหนักทุนตามเวลาหรือตามจำนวนไม้** — ได้ตัวเลขตัวเดียวที่ดูเรียบร้อย แต่ไม่ใช่ผลตอบแทน
  ของทุนก้อนไหนเลย · เป็นการแต่งตัวหารขึ้นมาให้คำถามที่ตอบไม่ได้มีคำตอบ
- **หารด้วย bucket long อย่างเดียวตามไฟล์ design** — ทำให้ผลของฝั่ง short ถูกวัดกับเงินที่มัน
  ไม่ได้ใช้ และขัด ADR 8 · บันทึกไว้เป็น errata ที่ `api/report.py`
